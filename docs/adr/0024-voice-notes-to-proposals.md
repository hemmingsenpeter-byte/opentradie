# ADR 0024: Voice notes become validated action proposals

- Status: Accepted (Feature 1, Workflow B). Builds on [ADR 0014](0014-speech-to-text-adapter.md) and [ADR 0021](0021-agent-business-tool-gateway.md).
- Date: 2026-10-20

## Context

A tradesperson finishing a job wants to say "Finished the job at Smith's house. One and a half hours labour, $185 mixer from Reece. Prepare the invoice and remind me to check the hot water cylinder next year." and have the job updated. The speech adapters existed (ADR 0014) but had no route, task or UI. The hard rules apply: prices only from approved records, integer money, agents propose and owners approve, `LOCAL_ONLY` fails closed with no fallback, and transcripts are never logged.

## Decision

1. **Storage (migration `0011_voice_notes.sql`).** `voice_notes` holds the uploader, the audio as a `documents` row (kind `other`, `job_id` NULL so it is not listed as job evidence), status (`uploaded → transcribing → transcribed → interpreting → proposed | needs_clarification | failed`), the provider transcript with provenance (provider, model, local/hosted, language, duration, duration-weighted average confidence, segments with a `lowConfidence` flag below 0.6), an optional owner correction (`corrected_transcript`, by, at), an `interpretation_version`, the server's resolution (customer, job, `job_hint | matched | owner_selected | ambiguous | not_found`), an owner-chosen labour rate, clarification JSON (questions, candidate jobs, rate options, notices) and a safe `error_code`. The original transcript is kept when corrected.
2. **Upload.** `POST /api/voice-notes` (owner, idempotent) takes base64 JSON like job evidence: `audio/m4a|mp4|mpeg|wav|webm|ogg`, at most 10 MiB, leading bytes must match the type; an optional `jobId` (from the job card) fixes the job. It stores the file through `FileStore` and queues `voice.transcribe` in the same transaction.
3. **Transcription.** `voice.transcribe` calls `transcribeWithPolicy`, so the privacy decision precedes any byte leaving the process; a denial records `MODEL_POLICY_DENIED` (audited as `model.policy_denied`, purpose `speech_transcription`) and no other provider is tried. Configuration: `SPEECH_PROVIDER=none|whisper_cpp|openai_compatible|mock` with `SPEECH_BASE_URL`, `SPEECH_MODEL`, `SPEECH_API_KEY`. The default is `none` (the note fails visibly with `SPEECH_NOT_CONFIGURED` and the owner can type the transcript). `mock` returns a fixed synthetic transcript and is refused at start-up when `NODE_ENV=production` or the profile is `cloud`.
4. **Interpretation.** `voice.interpret` applies the model policy for the agent runtime, then asks it for a strict extraction (`packages/agent/src/voice.ts`): customer name and address words (hints), `jobCompleted`, labour hours as spoken, materials with the amount _exactly as stated_ plus whether it was described as a cost or price, and `prepare_invoice` / `reminder {text, due relative|absolute}` actions. The schema has no tool names, ids, prices, dates-as-instants, approve or send fields; anything else is `AGENT_INVALID_OUTPUT`. The transcript is wrapped in an unguessable boundary. The mock runtime implements the canonical example deterministically; a real runtime without the capability fails closed (OpenClaw implements it since the 2026-10-21 amendment).
5. **The server decides everything authoritative.** Customer via `resolveCustomer`, then open jobs of that customer (narrowed by address words). Zero or several candidates → `needs_clarification` with candidates, and no proposals. Labour uses the single approved active hourly rate (or the one matching the rate hint, or the owner's choice); several → clarification. Hours become `quantityMilli`. A stated amount is parsed by `parseStatedAmountCents` into integer cents and always proposed as `reportedUnitCostCents` (supplier cost, never a sell price); the sell price comes from the existing executor (owner markup or business default; `MARKUP_REQUIRED` otherwise), with clarifications when the speaker called it a price or no default markup is set. "Finished the job" proposes `job.update_status → completed` only when the lifecycle allows it. Reminder dates are computed by `voiceReminderDueAt`: the local recording date plus the period (29 Feb + 1 year = 28 Feb) at 09:00 business time, from the note's creation time so re-interpretation is stable. A `job.add_note` carries the transcript.
6. **Proposals only.** Each call goes through `parseToolCall` and `createProposal` with source `voice`, `source_ref` = voice note id, idempotency key `voice-<id>-v<version>-<index>-<tool>`, and `allowAutoExecute: false`. Re-running a version returns the same proposals. `invoice.prepare` is created pending even while its executor is unavailable.
7. **Correction and clarification.** `PATCH /api/voice-notes/:id/transcript` and `POST /api/voice-notes/:id/clarify {jobId?, rateCode?}` (owner, idempotent) bump the version, mark that note's pending or failed proposals `superseded`, and queue a new interpretation; stale tasks do nothing.
8. **PWA.** A voice panel on Home ("Record update") and the job card: MediaRecorder where available, `accept="audio/*" capture` file fallback, status polling, low-confidence segments highlighted, transcript editing, job and rate pickers, the resulting proposals and a link to the Approval inbox.

## Consequences

- Implemented and tested with the mock transcriber, mock agent and real PostgreSQL (`tests/integration/voice-notes.test.ts`, `tests/e2e/voice-note.spec.ts`). No real speech engine or model has been exercised: whisper.cpp and OpenAI-compatible adapters remain **Implemented, not integration-tested**.
- Confidence is per segment, not per word; highlighting marks whole segments.
- Audio and transcripts are customer data kept until the business deletes them (no automatic retention job yet); they are included in backups. Audit rows hold ids, provider labels, counts and lengths only.
- Voice tasks run in the API process, like inbox tasks, because they need the agent runtime.
- whisper.cpp decodes WAV only unless started with `--convert`; browser recordings (WebM/MP4) need conversion first. This is unverified.

## Amendment (2026-10-21): extraction over the OpenClaw Gateway

`RealOpenClawAgentRuntime.extractVoiceNote` sends the delimited `buildVoiceExtractionPrompt` over `chat.send` and validates the final message with the same `voiceExtractionSchema`; a single fenced JSON block is tolerated, anything else is `AGENT_INVALID_OUTPUT` with no retry. Errors and timeouts become `AGENT_UNAVAILABLE`; the model policy (`LOCAL_ONLY` fails closed for hosted) is applied before any Gateway call. With a fake Gateway replaying the mock extraction, the canonical note yields exactly the mock path's proposals (`tests/integration/voice-notes.test.ts`). **Implemented, not integration-tested** against a live OpenClaw Gateway and model.
