# Architecture

OPENTRADIE is a modular monolith: one TypeScript codebase, one API process, one PostgreSQL schema. The same code runs in three deployment profiles (local, cloud, hybrid); only configuration, adapters and packaging differ ([ADR 0003](adr/0003-one-product-three-deployment-profiles.md)).

## Status vocabulary

Workspaces: `apps/api`, `apps/web`, `packages/core` (pricing, GST, quote versions, approval rules, privacy policy), `packages/documents` (quote and invoice PDF rendering), `packages/database` (schema, SQL migrations, seed), `packages/agent` (runtime adapters), `packages/integrations` (accounting contract, Xero adapter, speech-to-text adapters, credential envelope), `packages/platform` (runtime configuration, Postgres job queue and task handlers, relay contract, file stores, embedding providers, logical backup, installation claim), `apps/worker` (standalone queue worker; the API also runs the worker in-process unless `RUN_WORKER=false`).

## Rules that shape the code

- Agents propose; the backend validates; owners approve. Business tools reach the agent only as tenant-scoped reads and action proposals over an authenticated MCP endpoint ([ADR 0021](adr/0021-agent-business-tool-gateway.md)); there is no send, approve, shell, filesystem, database or price-setting tool.
- All material side effects go through validated API services and are audited.
- Money is integer cents; prices come from approved rate records ([ADR 0007](adr/0007-integer-cents-deterministic-pricing.md)).
- `tenant_id` comes from the authenticated session, never from client input ([ADR 0006](adr/0006-single-tenant-runtime-tenant-id-from-auth.md)).
- Privacy mode is enforced server-side and fails closed ([ADR 0005](adr/0005-privacy-modes-fail-closed.md)).
- OpenClaw is an external runtime reached only through its Gateway protocol ([ADR 0002](adr/0002-openclaw-gateway-client-only-agent-runtime.md)).

## Request flow: enquiry to accepted quote

1. The owner submits an enquiry (`POST /api/enquiries`).
2. The API gathers tenant-scoped context (customers, notes, approved rates) and calls `AgentRuntime.interpret`. Under the current privacy mode the policy check runs first.
3. The agent returns a proposal (customer query, rate code, quantity). The backend validates it against real records, asks for clarification if ambiguous, and never trusts agent-supplied prices.
4. `calculateQuote` selects approved-rate lines and records assumptions and missing information; the draft (numbered `Q-0001`, …) is priced and totalled by the core GST engine with the business's tax settings.
5. The owner may edit draft lines (`PATCH /api/quotes/:id`: approved rates, material cost plus markup, or an owner-entered price; fractional quantities, tax codes, discounts). The server reprices every line and recalculates GST; clients never send totals.
6. The owner approves (`POST /api/quotes/:id/approve`); only the `owner` role can, and an audit event is written in the same transaction.
7. The owner sends (`POST /api/quotes/:id/send`): the PDF is rendered and stored, a single-use acceptance link is issued (only its SHA-256 is stored), and an outbound message **draft** with the link is recorded. Nothing is emailed; there is no email provider yet.
8. The customer opens `/q/<token>` (no sign-in) and accepts or declines with a typed name (`POST /api/public/quotes/:token/accept|decline`). The decision, an append-only `quote_decisions` record, a `customer` audit event and a timeline event are written together. See [ADR 0018](adr/0018-quote-sending-and-customer-acceptance.md).

The OpenAPI document at `/api/openapi.json` is authoritative for routes. Every mutation needs an `Idempotency-Key` header and an `Origin` equal to `APP_ORIGIN`.

## Routes

`GET /health` (public; 200 with `ok` or `degraded`, 503 when the database is unavailable) and `GET /api/openapi.json`. Authenticated by session cookie: `POST /api/auth/login` (10 per minute), `POST /api/auth/logout`, `GET /api/me`, `GET /api/state`, `GET /api/search?q=`, `GET /api/communications`, `GET /api/rates`, `GET /api/audit-events`, `GET|POST /api/customers`, `GET|PATCH|DELETE /api/customers/:id` (DELETE archives), `POST|GET /api/customers/:id/contacts`, `POST /api/customers/:id/properties`, `GET /api/properties?q=&customerId=`, `GET|PATCH|DELETE /api/properties/:id` (DELETE archives), `GET|POST /api/jobs`, `GET|PATCH /api/jobs/:id` (GET is the job card: job, customer, property, allowed next statuses, notes, documents, quotes and timeline; PATCH validates status transitions and returns 409 `INVALID_STATUS_TRANSITION` or `REOPEN_REQUIRED`), `POST /api/jobs/:id/notes`, `POST /api/jobs/:id/evidence` (JSON with base64 content; JPEG, PNG, WebP, HEIC or PDF up to 6 MiB, bytes must match the type; 8 MiB body limit on this route only), `GET /api/documents/:id/content`, `GET /api/export` (owner only, audited), `POST /api/enquiries`, `GET /api/quotes`, `GET|PATCH /api/quotes/:id` (PATCH edits draft lines), `POST /api/quotes/:id/approve`, `POST /api/quotes/:id/reject`, `POST /api/quotes/:id/send`, `POST /api/quotes/:id/revise`, `GET /api/quotes/:id/pdf`, `GET|PATCH /api/settings/business` (GST registration and number, price entry, validity, default markup), `GET /api/approvals`, `GET /api/model-policy`, `POST /api/model-approvals`, `GET /api/proposals?status=&jobId=`, `GET /api/proposals/:id`, `POST /api/proposals/:id/approve` (optional edited payload and owner markup; executes in one audited transaction, idempotent; 422 `PROPOSAL_FAILED` records a refusal), `POST /api/proposals/:id/reject` (reason required), `GET /api/agent-tools`, `POST /api/agent-tool-policies` (only `job.add_note` may be `auto`), `POST /api/jobs/:id/assistant-actions` (mock planner; creates proposals only), inbox ([ADR 0022](adr/0022-unified-inbox-and-email-ingestion.md)): `GET /api/inbox/threads?filter=`, `GET|PATCH /api/inbox/threads/:id`, `POST /api/inbox/threads/:id/read`, `POST /api/inbox/threads/:id/link`, `POST /api/inbox/threads/:id/create-job`, `POST /api/inbox/paste` (1 MiB body limit), `PATCH /api/communications/:id` (edit a draft), `POST /api/communications/:id/discard`, `POST /api/communications/:id/approve-send`. `POST /agent-tools/mcp` (MCP tool gateway, 120 per minute) exists for the OpenClaw Gateway, is authenticated by the `AGENT_TOOL_TOKEN` bearer secret rather than a session, and answers 503 when that is unset. Public, no session, reached only with an acceptance token (30 GET and 10 POST per minute; POSTs still need `Origin` = `APP_ORIGIN`): `GET /api/public/quotes/:token`, `GET /api/public/quotes/:token/pdf`, `POST /api/public/quotes/:token/accept`, `POST /api/public/quotes/:token/decline`. The PWA renders the customer page at `/q/:token`. `POST /relay/v1/events` exists only when `RELAY_SHARED_SECRET` is set, and `POST /inbound/email/:provider` (21 MiB body limit, 120 per minute) only when `INBOUND_EMAIL_SECRET` is set; both are authenticated by HMAC signature, not a session. Every mutating business route requires the `owner` role (a viewer gets 403). Other limits: 300 requests per minute globally, 600 for the relay route, 60 for evidence uploads, 10 for export, 64 KiB request bodies except evidence uploads, pasted emails and inbound email.

Job status transitions are decided only by `packages/core/src/job-status.ts`: `new` to `quoted`, `scheduled`, `in_progress` or `cancelled`; `quoted` to `scheduled`, `in_progress` or `cancelled`; `scheduled` to `in_progress` or `cancelled`; `in_progress` to `completed` or `cancelled`. A `completed` job can be reopened to `in_progress` and a `cancelled` job to `new`, only with `reopen: true`. Each job mutation (create, status, property, details, note, evidence, quote draft, edit, approval, rejection, send, customer acceptance or decline, expiry, revision) appends a `job_events` row in the same transaction ([ADR 0017](adr/0017-job-lifecycle-and-append-only-timeline.md)).

Voice notes ([ADR 0024](adr/0024-voice-notes-to-proposals.md)): `POST /api/voice-notes` (owner; base64 audio, optional `jobId`), `GET /api/voice-notes?jobId=`, `GET /api/voice-notes/:id` (with proposals), `PATCH /api/voice-notes/:id/transcript` and `POST /api/voice-notes/:id/clarify` (owner; supersede pending proposals and re-interpret). Tasks `voice.transcribe` and `voice.interpret` run in the API process.

Scheduling ([ADR 0019](adr/0019-scheduling-and-reminders.md)): `GET /api/appointments?from=&to=&jobId=&includeCancelled=` (range up to 100 days), `GET /api/appointments/:id` (with reminders), `GET /api/jobs/:id/appointments`, `POST /api/appointments` (409 `APPOINTMENT_CONFLICT` with conflicting ids unless `allowConflict: true`; a confirmed booking moves a `new` or `quoted` job to `scheduled`), `PATCH /api/appointments/:id` (reschedule; 409 `VERSION_CONFLICT` on a stale `version`), `POST /api/appointments/:id/confirm`, `POST /api/appointments/:id/cancel`, `GET /api/scheduling/availability?date=&durationMinutes=&days=&limit=` (free slots in the business time zone, DST-aware), `GET|PATCH /api/scheduling/settings` (working hours, travel buffer, reminder lead time). Mutations are owner-only, idempotent and audited.

Structured JSON logs (Fastify/pino) with a request ID returned to clients, a `/health` endpoint that checks the database, and log redaction rules: never log message bodies, credentials, prompts or provider responses. Metrics endpoint: Planned.
