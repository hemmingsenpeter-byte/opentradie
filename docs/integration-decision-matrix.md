# Integration decision matrix

Companion to [open-source-assessment.md](open-source-assessment.md) (evidence, versions, licence text) and [architecture-v2.md](architecture-v2.md). Status of every row: **Planned** unless it says "existing". Versions and licences were read on 2026-10-19; "unverified" means it could not be confirmed.

Decision vocabulary: **USE** (library in our code), **SERVICE** (separate process behind an adapter), **REFERENCE** (read for concepts, copy nothing), **DEFER** (revisit after the listed trigger), **REJECT**.

## Build versus adapt (qualitative)

Assumptions: [open-source-assessment.md](open-source-assessment.md#assumptions-behind-the-build-versus-adapt-estimates). S = days, M = 1 to 3 weeks, L = more than a month.

| Capability                        | Decision                   | Build effort if custom | Effort with the chosen option               | Note                                                         |
| --------------------------------- | -------------------------- | ---------------------- | ------------------------------------------- | ------------------------------------------------------------ |
| Agent runtime                     | Adapt (OpenClaw)           | L                      | S (client exists) + M (tool gateway)        | Tool gateway is ours                                         |
| Durable background work           | Build on existing queue    | M                      | S (outbox table + dispatcher)               | pg-boss would also need S to M integration, so little saving |
| Speech to text                    | Adapt (whisper.cpp)        | L                      | S to M (adapter, audio conversion, storage) |                                                              |
| PDF documents                     | Adapt (react-pdf)          | M                      | S to M (templates, fonts)                   |                                                              |
| Money and tax                     | Build (extend `money.ts`)  | S                      | S                                           | Already tested                                               |
| Accounting sync                   | Adapt (xero-node)          | L                      | M (mapping, conflicts, sandbox tests)       |                                                              |
| Calendar UI                       | Adapt (FullCalendar)       | M                      | S to M                                      |                                                              |
| Inbox and channels                | Build native               | L                      | M for email first                           | Chatwoot would add M of glue and a second store              |
| Backup                            | Adapt (restic)             | M                      | S                                           |                                                              |
| CRM, field-service, invoicing UIs | Build (reference concepts) | M each                 | M each                                      | Copyleft blocks reuse                                        |

## Lists

**Necessary for the MVP (Phases 1 to 3):** PostgreSQL, OpenClaw (existing), react-pdf, xero-node. Everything else is later or optional.

**Duplicates of existing OPENTRADIE capability:** pg-boss and Temporal (job queue), Dinero.js (money), Chatwoot (communications), cal.diy and FullCalendar server logic (the appointments model is ours), ERPNext/InvoicePlane (invoice and quote logic).

**Reference-only (no code copied):** OCA/field-service, ERPNext, Twenty, EspoCRM, InvoicePlane, cal.diy, pg-boss, Dinero.js (allocation idea), Chatwoot (conversation model).

**Unacceptable complexity:** Temporal (cluster), Chatwoot (Rails, Redis, Sidekiq, second message store), ERPNext/Odoo (full ERP stacks), Twenty (separate CRM stack).

**Licensing risks:**

- AGPL-3.0: OCA/field-service, Twenty core, EspoCRM. GPL-3.0: ERPNext. Not to be linked, bundled, copied or translated into code.
- Dual-licence files: Twenty (`@license Enterprise`), Chatwoot (`enterprise/`), Activepieces (`ee`). Avoid the commercial directories.
- FullCalendar premium packages (`@fullcalendar/resource-timeline` reports `SEE LICENSE IN LICENSE.md`). Do not install them.
- InvoicePlane: trademark notice and CodeIgniter licence alongside an MIT-style text; exact SPDX unverified.
- Optional MinIO in the cloud compose profile is AGPL-3.0 upstream (from [UPSTREAM.md](UPSTREAM.md)); it is a separate service, never linked.
- Whisper model weights, OpenClaw model providers and Xero API terms carry their own terms; none reviewed.

**Deferrable:** Expo, React Native Paper, Activepieces, PaddleOCR, MarkItDown, faster-whisper (optional), rclone (optional), FullCalendar until Phase 6.

**Needs Python, containers, hosting or commercial APIs:**

| Item                                                      | Needs                                                                |
| --------------------------------------------------------- | -------------------------------------------------------------------- |
| faster-whisper                                            | Python 3.9 or later, container, GPU host for speed                   |
| PaddleOCR, MarkItDown                                     | Python sidecar (deferred)                                            |
| Chatwoot, Activepieces, Temporal                          | Containers and extra stateful services (rejected or deferred)        |
| Xero                                                      | Commercial API, tier pricing (unverified), app registration, sandbox |
| Email (Gmail OAuth or Microsoft Graph), WhatsApp Business | Provider accounts and commercial terms                               |
| Hosted LLM providers                                      | Commercial APIs; blocked by `LOCAL_ONLY`                             |
| whisper.cpp                                               | Native binary and model files on the host                            |

**Wrapped behind provider interfaces** (so the business logic never imports a vendor SDK): `AccountingAdapter` (Xero), `SpeechToText` (whisper.cpp, faster-whisper, mock), `MailProvider`, `CalendarProvider`, `MessagingProvider`, `FileStore` (exists: local FS and S3), `AgentRuntime` (exists), `LLM`/embeddings (exists for embeddings). Contract and failure behaviour per adapter are in [architecture-v2.md](architecture-v2.md).
